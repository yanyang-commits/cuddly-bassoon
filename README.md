# ONESTEL · 高质量提问与项目行动

**把模糊想法变成可执行任务。** ONESTEL 以高质量提问为主要功能，帮助用户生成可交给 AI 的任务指令，再通过工具导航与实践笔记推进项目。

[高质量提问](https://yanyang-commits.github.io/cuddly-bassoon/prompt/) · [访问网站](https://yanyang-commits.github.io/cuddly-bassoon/) · [AI 工具导航](https://yanyang-commits.github.io/cuddly-bassoon/tools/) · [阅读文章](https://yanyang-commits.github.io/cuddly-bassoon/articles/) · [构建与部署记录](https://github.com/yanyang-commits/cuddly-bassoon/actions)

## 项目概览

ONESTEL 面向有想法、却难以把任务说清楚的人。核心路径是：描述模糊问题 → 整理高质量指令 → 交给合适的 AI → 核验输出并推进项目。实践笔记与工具导航为这条路径提供支持。当前已部署到 GitHub Pages；ONESTEL 为项目品牌，尚未确认 `onestel.com` 的归属或配置。

- **高质量提问工作台**：6 类任务方向，目标、背景与约束补充，缺口提示，可编辑指令、复制、TXT 下载及示例。
- **内容站**：首页、文章列表、3 篇原创方法文章、关于页及 404 页面。
- **AI 工具导航**：73 个工具与平台、10 个分类，涵盖国内外常见创作与工作场景。
- **组合筛选**：关键词、用途分类、使用方式与“入门优先”可同时使用，支持无结果提示及重置。
- **静态优先**：文章正文和全部工具卡片在构建时生成；关闭 JavaScript 仍可阅读并访问工具官网。
- **发布基础**：独立页面标题、描述、canonical、Open Graph、站点地图与 robots.txt；静态资源带内容指纹参数。

当前没有站内 AI 调用、用户登录、数据库、实时新闻采集、邮件订阅提交或后台编辑。工具导航提供外部产品入口，不代表站内已经集成这些服务。


## 高质量提问工作台

在 `/prompt/` 输入模糊想法，选择项目探索、学习新知识、职业判断、创作与写作、方案比较或执行与复盘。可选填写目标、背景、约束与输出形式，点击生成后编辑、复制或下载指令。未填写的信息会标为待确认，不代替用户编造条件。

当前采用浏览器内的提问框架组合，不调用 AI 模型，不上传或持久化输入；指令要求 AI 区分证据与推断、集中提出最多三个关键问题、挑战假设，并给出验收标准及最小下一步。模型回答仍由用户核验。

`public/assets/prompt-core.js` 维护生成逻辑，`prompt.js` 负责表单与导出，`scripts/render-prompt.mjs` 维护页面。复制失败时会选中结果并提示手动复制。后续可按实际使用反馈接入服务端自适应追问，当前未实现。

### 使用流程

1. 写下原始想法，选择任务方向；原始想法为必填项，最多 6000 字。
2. 按需展开补充条件，说明目标与成功标准、背景材料、时间和预算约束，以及期望输出形式。
3. 点击“生成任务指令”，查看关键缺口提示，并编辑结果。
4. 复制到你使用的 AI，或下载 TXT；自动复制受限时按页面提示手动复制。
5. 根据 AI 的关键追问补充条件，核对证据，按最小下一步推进任务。

| 任务方向 | 指令关注点 |
| --- | --- |
| 项目探索 | 目标用户、需求频率、替代方案、获客路径与最小验证 |
| 学习新知识 | 核心机制、适用边界、反例与理解自测 |
| 职业判断 | 可迁移能力、岗位证据、机会成本与可逆试错 |
| 创作与写作 | 读者、观点、材料依据与表达要求 |
| 方案比较 | 统一口径、成本风险、维持现状基准与条件变化 |
| 执行与复盘 | 里程碑、依赖、结果证据与下一轮调整 |

### 输入与输出示例

原始想法：“我想做一个独立站。”

可以补充：“面向不知道如何描述 AI 任务的新手；先交付一个能生成并复制任务指令的页面；优先低维护，无需登录；输出实现步骤与验收清单。”

生成结果会组织为原始想法、任务方向、目标、背景、约束、期望输出和工作方式，并要求 AI 提出必要追问、比较基准方案、说明反证与给出最小行动。这里只展示使用思路，不表示示例项目已经由模型完成。

### 当前能力与限制

- 生成器使用浏览器内规则组合，**尚未接入模型进行语义理解、自动诊断或多轮追问**。缺口提示依据字段是否填写，不代表内容质量评分。
- 原始想法及补充内容不上传、不持久化；刷新页面可能丢失未导出的输入。复制或下载后，内容由你自行管理。
- 生成指令需要 JavaScript；文章与工具导航可在关闭 JavaScript 时浏览。
- 指令帮助明确任务，不能保证外部 AI 的答案正确，也不会自动执行、发布或替用户完成项目。
- 输出可手动编辑；空白输入不能生成；未提供的条件保持待确认，不编造身份、预算或成果。

## 本地启动

先安装 **Node.js 24 或以上版本**，再执行：

```bash
git clone https://github.com/yanyang-commits/cuddly-bassoon.git
cd cuddly-bassoon
npm run dev
```

打开 [本地预览](http://localhost:4321/cuddly-bassoon/)。预览服务只监听本机 `127.0.0.1:4321`，不用于生产服务。当前没有热更新；修改文件后按 `Ctrl+C` 停止服务，再运行 `npm run dev`。

| 命令 | 用途 |
| --- | --- |
| `npm run build` | 生成页面、静态资源、sitemap.xml、robots.txt 和 404 |
| `npm run check` | 检查已生成的站内链接和资源；先运行 build |
| `npm run dev` | 重新构建并启动本地预览 |

## 高质量提问功能维护

在 `public/assets/prompt-core.js` 中维护各任务方向的引导与通用工作方式。修改时检查空输入、仅原始想法、完整条件、六类任务方向及未知条件标注；新增方向时同步 `scripts/render-prompt.mjs` 的选项和 `public/assets/prompt.js` 的示例。页面文案与输入结构在 `scripts/render-prompt.mjs` 中维护，样式在 `public/assets/style.css` 中维护。

构建会为提问脚本及其生成逻辑模块添加内容指纹参数。调整后重新构建发布，不直接修改 `dist/`。

## 内容维护

### 添加文章

在 `content/posts.json` 数组中复制现有记录并修改。字段示例：

```json
{
  "slug": "my-first-ai-workflow",
  "title": "用一个真实任务验证 AI 工作流",
  "category": "AI 实践",
  "date": "2026-10-10",
  "summary": "交代读者将解决的问题，以及文章提供的方法。",
  "paragraphs": [
    "第一段说明任务、背景和约束。",
    "第二段记录方法、结果和仍需核验的信息。"
  ]
}
```

`slug` 使用唯一的小写英文、数字与连字符；日期使用 `YYYY-MM-DD`。`paragraphs` 是纯文字段落，构建器会转义 HTML，当前不解析 Markdown。正文要区分事实、判断和待核验信息，不把未执行的尝试写成实际经验。

| 编程与建站 | 10 | 图像与设计 | 7 |

在 `content/tools.json` 中添加或编辑记录，结构示例：

```json
{
  "name": "工具名称",
  "url": "https://example.com/",
  "category": "图像与设计",
  "description": "简洁说明工具的主要用途。",
  "task": "矢量图、品牌视觉与设计资产",
  "mode": "网页 / API",
  "tags": ["矢量", "图像", "品牌"],
  "featured": false,
  "verifiedAt": "2026-10-10",
  "sourceUrl": "https://example.com/"
}
```

这里的 `example.com` 是字段示意，正式收录时替换为确认过的 HTTPS 官方地址。名称保持唯一，分类优先沿用已有方向。`mode` 使用包含“网页”“API”“本地”或“自部署”的明确文字，以便筛选脚本识别；`featured` 为布尔值，表示编辑建议的“入门优先”。

收录前核对官网、产品名称和实际入口，更新 `verifiedAt`，并同步 [官方来源清单](docs/TOOL_SOURCES.md)。如增减条目，同步本 README 的总数与分类数量；页面数量和分类选项会从数据自动生成。页面展示的统一核对日期目前在 `scripts/render-tools.mjs` 中维护，整批复核时需一并更新。

最新一批官网资料核对日期为 **2026-10-10**。本目录覆盖代表性工具，不宣称穷尽所有优秀产品，也不等于逐项性能测试或排名。产品功能、价格、额度、许可与地区可用性以官方最新说明为准。

## 验证与发布

更新内容后运行：

```bash
npm run build
npm run check
```

再用本地浏览器检查页面：提问工作台的空输入、示例、完整条件、结果编辑、复制受限回退、TXT 下载与清空；导航与文章链接；工具组合筛选、无结果提示与重置；窄屏下的换行和横向溢出。自动检查只能验证部分结构与链接，不能代替视觉检查，也不会核验外部官网是否仍可访问。

有仓库写入权限时，可以提交到 main：

```bash
git add README.md content/posts.json content/tools.json
git commit -m "Update ONESTEL content and documentation"
git push origin main
```

根据实际修改选择提交文件。多人协作时建议新建分支并发起 Pull Request；远端有新提交时先合并，避免强推覆盖。

当前 Pages 已配置为 **GitHub Actions**：

1. Pull Request 到 main：运行构建与链接检查，不发布。
2. 推送到 main：构建、检查、上传 `dist/` 并发布到 Pages。
3. 需要重新发布时，在 Actions 中手动运行 `Build and deploy Pages` 工作流。

如复制到其他仓库，先在 Settings → Pages 中选择 GitHub Actions，并调整 `site.config.json` 的地址和子路径。

### 更换域名或部署路径

当前配置为：

```json
{
  "name": "ONESTEL",
  "description": "把模糊想法变成可执行的 AI 任务指令，帮助人们更好地完成项目。",
  "url": "https://yanyang-commits.github.io",
  "basePath": "/cuddly-bassoon"
}
```

`url` 是网站来源地址，不包含部署子路径；`basePath` 是仓库站点的路径。迁移到自有域名根目录时，将 `url` 改为实际 HTTPS 域名，将 `basePath` 设为 `""`，再构建发布。DNS、Pages 自定义域名与 HTTPS 需要单独配置；本仓库没有默认添加 `CNAME`。

### AI 接入原则

GitHub Pages 只托管静态文件，模型调用需要独立服务端。[AI 接入方案](docs/AI_INTEGRATION.md) 保留早期“笔记 → 提纲”设计，可作为基础安全参考；新主功能的自适应追问 API 尚未设计或实现。接入时：密钥仅保存在服务端；设置请求长度、超时、限流和费用上限；前端清楚标注输出需要核验。不要把密钥写入 JSON、前端脚本、配置文件或 Git，也不要直接插入未经处理的模型 HTML。

## 常见问题

**这是 AI 自动改写吗？** 当前是本地提问框架组合。站点不会调用模型理解你的想法；把生成的指令复制到外部 AI 后，才由该服务进行回答或执行。

**生成了指令就能完成项目吗？** 还需要补充关键条件、核验 AI 输出并执行最小行动。生成器提供任务起点，不保证完成结果。

**为什么修改后没有变化？** 本地需要重新运行 `npm run dev`；线上查看 Actions 是否成功部署，再刷新页面。资源内容指纹有助于加载新版本，但部署完成前页面仍可能显示旧内容。

**为什么运行 check 报文件不存在？** 先执行 `npm run build`，检查脚本读取的是 `dist/`。

**为什么首页或样式出现 404？** 核对 `url`、`basePath` 与实际部署地址是否一致；仓库 Pages 使用 `/cuddly-bassoon/`，不是域名根目录。

**可以在正文里写 Markdown 或 HTML 吗？** 当前正文只支持纯文字段落。需要图片、代码块或复杂排版时，应先扩展内容结构和构建模板。

**站点会保存工具搜索记录吗？** 当前筛选只在浏览器完成，站点不保存搜索记录，也没有站内分析统计。访问外部工具官网后，其服务政策独立适用。
