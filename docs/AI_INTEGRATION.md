# AI 功能接入方案（未来设计，尚未实现）

静态站作为 UI；独立的服务端 API（例如 Cloudflare Worker）持有密钥并调用模型。GitHub Pages 只承载静态文件，不能执行服务端模型请求。

第一个功能建议：笔记 → 文章提纲。用户手动粘贴文本并点击生成，清楚标识 AI 输出需要核验。先不做全网热点采集或自动发布。

拟定接口：POST /api/outline，请求 {"text":"笔记内容"}；成功响应 {"outline":["要点一","要点二"]}。错误返回标准状态码和 {"error":{"code":"RATE_LIMITED","message":"请稍后重试"}}。前端未来放在 public/assets/ai.js；API 单独仓库/目录维护。

实现顺序：1. 后端密钥环境变量；2. 请求大小和字符长度上限；3. 服务端限流与每日费用上限；4. 固定提示模板；5. 超时、失败反馈；6. 前端配置非秘密 API 地址与接入按钮。先确定模型再按其官方 SDK 文档实现，不预埋虚假接口。

密钥不写入 content、public、site.config 或 Git。仅设置 CORS 白名单无法阻止第三方消耗额度，需要服务端额度控制；如有用户私有数据再添加认证。默认不持久化原文，不把全文记录到日志；若未来要存储，先说明用途和保留期限。前端把模型输出作为文字显示，不能直接插入未经处理的 HTML。

本版本没有 AI 请求按钮，避免给读者造成已经接入的误解。静态内容与未来 API 相互独立，可单独更新。
