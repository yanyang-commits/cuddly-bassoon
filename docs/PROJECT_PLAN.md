# MVP 项目规划

## 首页信息架构
1. 顶部：ONESTEL 品牌与首页 / 文章 / 工具 / 关于导航。
2. 首屏：一句定位“把科技变成可用的东西”、简短说明、阅读笔记入口。
3. 三个栏目：AI 实践、独立站、数字工具。
4. 最新笔记：分类、时间、标题、摘要和详情链接。
5. 下一步入口：工具导航。
6. 页脚：项目说明，启动阶段明确示例内容。

## 首批页面
| 路径 | 目的 | 当前功能 |
| --- | --- | --- |
| / | 说明定位和阅读路径 | 栏目与最新文章 |
| /articles/ | 找文章 | 按标题、分类、摘要筛选 |
| /articles/start-small/ | 第一篇独立站文章 | 静态正文 |
| /articles/ai-workflow/ | 第一篇 AI 文章 | 静态正文 |
| /tools/ | 给出可执行入口 | 官方工具链接 |
| /about/ | 建立项目认知 | 定位与更新方式 |
| /404.html | 错误地址恢复 | 返回首页 |

所有路径在仓库 Pages 部署时前置 /cuddly-bassoon。品牌和内容都可替换。

## 迭代顺序
第一周：运行构建，替换两篇示例；完成三篇原创实践笔记；确认品牌，再提交并部署。验收：手机可阅读、导航可达、文章链接和资源检查通过。
第二至四周：每周一篇实践；增加 RSS 与标签页；观察读者对哪些问题有反馈。验收：每篇写清问题、过程、结果，不靠填充内容扩页。
第二个月：按真实需求接入一个 AI 小工具，例如用户输入笔记后生成待核验提纲；先做独立服务端 API、额度限制与错误处理。验收：成功、超时、空输入与额度耗尽均有可理解反馈。
第三个月：验证订阅意愿，再接入实际邮件服务；确认隐私说明与退订流程。需要用户账户或持久记录时才引入数据库。
后续：内容达到约 20–30 篇、多人编辑或模板复杂时，再评估迁移 Astro + Markdown；需要大量服务端交互时再评估应用框架。不要把迁移本身当成果。

## 维护预算
每周一次：写一篇、检查链接、构建并发布。每月一次：检查 Node.js 与 Actions 支持状态、失效工具链接和依赖策略。当前无第三方运行时依赖；代价是正文只支持简单段落，复杂排版需扩展构建模板。

## SEO 与内容
每页独立 title、description、canonical 和 Open Graph；构建 sitemap.xml 和 robots.txt。正式部署域名必须与配置一致。暂不提供 OG 图片、RSS、分析统计或结构化文章数据。初版以原创内容质量优先，后续按需求增加。
